# UV Detector

Школьный проект с FastAPI и Telegram-ботом: принимает фотографию UV-TEST CARD,
находит область TEST AREA и возвращает интенсивность, пропускание и степень
защиты по ближайшему цвету учебной таблицы. Готовый клиент бота — `bot.py`.

## Что удалось извлечь из документов

По умолчанию API и бот используют `document_template`: 101 цвет с шагом защиты
1% из `UV_тесткарта_библиотека.docx`. Цвета и проценты сохранены как в документе,
включая направление шкалы. Возвращается ближайшая строка, даже если оттенок
фотографии не совпал с ней точно. Калиброванные значения можно будет подставить
после опытов, не переписывая API и бота.

В `Фото.docx` находятся пять фотографий с подписями: 691, 626, 595, 0 и
1500 мкВт/см². Последняя — контроль без барьера. Эти примеры доступны отдельно
через `library_id=photo_examples` и не определяют результат учебного режима.
Исходные изображения сохранены в `data/examples/`, обе библиотеки —
в `data/libraries.json`.

Бот добавляет короткую пометку «Расчёт по учебной шкале». В API пока возвращается
`measurement_validated: false`; шаг таблицы 1% обозначает её дискретность,
а не подтверждённую точность измерения.

## Запуск API

Нужны Python 3.14 и `uv`. Из корня проекта:

```bash
uv sync --locked
uv run uvicorn main:app --host 127.0.0.1 --port 8000
```

Swagger с загрузкой изображения: http://127.0.0.1:8000/docs.

```bash
curl http://127.0.0.1:8000/analyze \
  -F 'file=@data/examples/photo-1.png' \
  -F 'reference_intensity_uw_cm2=1500'
```

Маршруты: `GET /health`, `GET /libraries`, `POST /analyze`. Готовые запросы
для HTTP-клиента PyCharm находятся в `test_main.http`.

## Развёртывание API в FastAPI Cloud

В форме **Create From GitHub** выберите репозиторий `avlyubimov/uv-detector`
и имя проекта `uv-detector`. **Root Directory оставьте пустым**: `main.py`
и `pyproject.toml` находятся в корне репозитория.

При необходимости добавьте переменную `API_KEY` и отметьте её как секрет.
Для первого запуска API остальные переменные окружения не нужны. Нажмите
**Create App**; после успешного развёртывания откройте адрес приложения
с `/health` и `/docs` для проверки.

В проекте заданы Python 3.14, зависимость `fastapi[standard]` и точка входа
`main:app`. Эти настройки используются платформой при сборке и запуске.

Для работы Telegram-бота в этом же приложении Cloud добавьте две переменные:

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен от @BotFather; включите **Secret** |
| `UV_API_URL` | `https://uv-detector.fastapicloud.dev`, без `/docs` |

Нажмите **Save and Redeploy**. При запуске `main:app` приложение автоматически
инициализирует бота и регистрирует `POST /telegram/webhook` в Telegram.
Отдельный процесс `bot.py` для этого режима не требуется: бот работает в Cloud
при выключенном компьютере. Без `TELEGRAM_BOT_TOKEN` запускается только API.

Webhook проверяет секретный заголовок Telegram; секрет автоматически вычисляется
из токена и передаётся при регистрации. Дополнительная переменная не требуется.
Запрос подтверждается после обработки сообщения. Фото анализируется через
существующий `/analyze` внутри приложения, без HTTP-запроса к собственному
публичному адресу. При остановке приложения webhook сохраняется, чтобы
перезапуск или смена экземпляра не отключали доставку сообщений.

Остановите локальный запуск `bot.py` перед переходом на webhook: Telegram
не позволяет одновременно получать сообщения через polling и webhook.
Команда `/reference` хранит настройку в памяти экземпляра; после перезапуска
или попадания запроса в другой экземпляр используется контроль по умолчанию.

Официальная инструкция: https://fastapicloud.com/docs/getting-started/existing-project/.

## Локальный запуск Telegram-бота

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram, отправьте `/newbot`,
   выберите название и username с окончанием `bot`. Скопируйте выданный токен.
   [Официальная инструкция Telegram](https://core.telegram.org/bots/tutorial#obtain-your-bot-token).
2. Скопируйте `.env.example` в `.env`, если `.env` ещё нет. Добавьте токен в
   `TELEGRAM_BOT_TOKEN`. Файл `.env` исключён из Git.
3. В `UV_API_URL` уже указан облачный API `https://uv-detector.fastapicloud.dev`.
   Если на API задан `API_KEY`, добавьте такой же ключ в `.env` бота.
   Для локального API используйте `UV_API_URL=http://127.0.0.1:8000`.
4. Из корня проекта запустите:

```bash
uv sync --locked
uv run python bot.py
```

5. Откройте созданного бота, нажмите **Start** и отправьте фото UV-TEST CARD.
   Ответ содержит квадратный образец цвета тестовой области вместо HEX-кода;
   интенсивность, пропускание и защита указаны в подписи к изображению.

При локальном запуске процесс `bot.py` должен работать постоянно:
при закрытии терминала бот остановится. Для круглосуточной работы используйте
webhook в FastAPI Cloud, как описано выше.

Бот работает через long polling; публичный webhook для локального запуска
не нужен. `/start` показывает инструкцию, затем можно присылать фото или
изображение как файл. Файл предпочтительнее: Telegram не пересжимает его.
`/reference 1500` задаёт интенсивность без барьера для текущего чата до перезапуска.
Без команды используется контроль из исходного документа: 1500 мкВт/см².

Бот автоматически загружает `.env` рядом с `bot.py`. Уже заданные переменные
окружения имеют приоритет; их также можно задать в Run Configuration PyCharm.
API при запуске через `uvicorn` использует переменные окружения. Для локального
polling запускайте API без `TELEGRAM_BOT_TOKEN`: его наличие включает webhook.
Если задан `API_KEY`,
API требует `X-API-Key` для `/analyze` и `/libraries`; задайте тот же ключ боту.
Внешнее размещение требует HTTPS и ограничения частоты запросов на прокси.
Загруженные пользователями фото сервис не сохраняет и не отправляет во внешние
сервисы распознавания. Фотографии, отправленные боту, проходят через Telegram.

## Параметры анализа

`POST /analyze` принимает `multipart/form-data`:

| Поле | Назначение |
| --- | --- |
| `file` | JPEG, PNG, WebP или BMP; до 10 МБ, до 24 мегапикселей |
| `library_id` | `document_template` по умолчанию; `photo_examples` — дополнительный режим сравнения с пятью фото |
| `reference_intensity_uw_cm2` | Интенсивность без барьера; по умолчанию 1500 из документа |
| `roi` | Необязательный JSON `{"x":0.1,"y":0.5,"width":0.8,"height":0.2}` с областью TEST AREA |
| `white_roi` | Такой же JSON с белой неокрашенной областью для коррекции баланса белого |

Координаты ROI нормированы от 0 до 1 и относятся к изображению после применения
EXIF-ориентации. Без `roi` распознаётся конкретная карта UV-TEST CARD из примеров:
алгоритм исправляет перспективу и поворот, находит печатную шкалу для ориентации,
затем берёт цвет из TEST AREA. Шкала сверху не используется как измеряемая область.
При другой форме полоски нужно явно указать `roi` и желательно `white_roi`.
Белая область автоматически приводится к RGB (240, 240, 240); та же обработка
применена к фотоэталонам. Сильно тёмный белый фон отклоняется. При пересвете
белого края анализ продолжается с предупреждением о приблизительной коррекции.

Сравнение использует расстояние CIE76 (ΔE) в CIELAB и медианный цвет, устойчивый
к тексту и небольшим дефектам внутри TEST AREA. Полигон измеренной области,
исходный и скорректированный цвет доступны в `sampling` для проверки выделения.

Пример основных полей для первого исходного фото:

```json
{
  "library_id": "document_template",
  "status": "uncertain",
  "measurement_validated": false,
  "estimate": {
    "intensity_uw_cm2": 1380.0,
    "transmission_percent": 92.0,
    "protection_percent": 8.0
  },
  "reference_intensity_uw_cm2": 1500.0,
  "reference_intensity_source": "request"
}
```

В полном ответе также есть `nearest_matches`, `sampling` и `warnings`.
`estimated` означает предварительное сопоставление; `uncertain` — приблизительное
или неоднозначное совпадение; результат при этом возвращается. `no_match` означает,
что область слишком неоднородна или превышен заданный библиотекой порог цвета;
тогда `estimate` равен `null`. Три ближайших цвета остаются для диагностики.
В учебной таблице `max_color_distance: null`: ограничения на расстояние до
ближайшего цвета нет. В режиме фотоэталонов по умолчанию используется порог ΔE=12.

В учебном режиме защита берётся из выбранной строки таблицы,
`пропускание = 100 − защита`, `интенсивность = контроль × пропускание / 100`.
Например, при защите 8% и контроле 1500 получается 1380 мкВт/см².
В режиме фотоэталонов интенсивность берётся из подписи фото, а проценты
вычисляются относительно контроля. Если интенсивность превышает контроль,
защита возвращается как `null`.

Ошибки чтения файла и распознавания содержат `detail.code` и `detail.message`;
ошибки стандартной валидации FastAPI содержат список в `detail`.
Неподходящий формат — HTTP 415, большой файл — 413, ненайденная карта или
неверная ROI — 422. Если карта не найдена, не подставляется случайный цвет фона.

## Повторный импорт

```bash
uv run python -m scripts.import_references \
  --template '/home/avlyubimov/Загрузки/UV_тесткарта_библиотека.docx' \
  --photos '/home/avlyubimov/Загрузки/Фото.docx'
```

Импортёр читает реальные RGB/HEX из таблицы и изображения из соответствующих
строк DOCX, проверяет согласованность HEX/RGB, нормализует цвета фото тем же
алгоритмом и сохраняет SHA-256 исходных документов. Исходные DOCX не изменяются.
После изменения библиотеки или алгоритма выделения перезапустите API; при
изменении нормализации повторно импортируйте фотоэталоны.

## Замена данных после опытов

В `data/libraries.json` найдите объект с `id: "document_template"` и замените
его `samples` результатами калибровки. Для каждой строки нужны `id`, `rgb`
и `protection_percent`. Пример одной строки:

```json
{
  "id": "sample-01",
  "rgb": [142, 90, 184],
  "protection_percent": 50,
  "intensity_uw_cm2": null
}
```

Это пример формата, а не новые измеренные данные. `intensity_uw_cm2: null`
означает расчёт интенсивности из процента; если указать измеренную интенсивность,
она станет основой результата, а проценты будут вычисляться относительно
контроля. В библиотеке должно быть не менее двух строк; их количество может
отличаться от 101. RGB снимайте с той же обработкой баланса белого, которую
использует API: скорректированный цвет доступен в `sampling.rgb`.

После проверки данных обновите `title`, `source_document`, `source_sha256`,
`warnings`, `reference_intensity_uw_cm2` и отметку `calibrated`. Флаг
`calibrated: true` сообщает API, что данные проверены вами; он сам не выполняет
калибровку. При необходимости задайте `max_color_distance`, например 12, чтобы
отклонять цвета вне калиброванной шкалы. Перезапустите API. Бот продолжит
использовать тот же идентификатор библиотеки. Повторный импорт старого DOCX
перезапишет эти изменения исходной учебной таблицей.

В режиме `photo_examples` проверены все пять исходных фото и их варианты с поворотами
90/180/270° и JPEG-сжатием: 20 из 20 вариантов выбирают ожидаемый фотоэталон.
Также проверены EXIF, лимиты размера и разрешения, некорректные файлы, ROI,
авторизация и точное соответствие цвета исходной таблице. Это регрессионная
проверка на исходных примерах, а не оценка точности на независимых измерениях.

Для учебного режима дополнительно проверены шесть присланных фотографий,
их повороты и JPEG-сжатие, все 101 цвета таблицы и обработчики Telegram.
Все шесть фото дают результат; тестовая область выделяется автоматически.
